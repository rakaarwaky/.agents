# Step 0 — Detect Mergify (setup lane)

When the user runs `/pr-babysit setup <number>`:

Run only for the target PR's repo. Determines whether Mergify merge-queue is available
and bootstraps a `.mergify.yml` config when missing.

## Detect Mergify

Check in this order (stop at first positive):

### 1. Config file in the worktree

```bash
for f in .mergify.yml .mergify.yaml .mergify/config.yml .mergify/config.yaml .github/mergify.yml .github/mergify.yaml; do
  if [ -f "$f" ]; then
    MERGIFY_CONFIG="$f"
    MERGIFY_AVAILABLE="configured"
    break
  fi
done
```

### 2. Mergify check-runs on the PR

```bash
gh api "repos/$OWNER_REPO/commits/$(gh pr view <number> --json headRefOid -q .headRefOid)/check-runs" \
  -q '.check_runs[] | select(.app.slug == "mergify") | .name' 2>/dev/null | head -1
```

Non-empty result → `MERGIFY_AVAILABLE="installed"` (app installed, no local config).

### 3. Default

No config, no check-runs → `MERGIFY_AVAILABLE="none"`.

## Bootstrap `.mergify.yml` (when `MERGIFY_AVAILABLE` is `"none"` or `"installed"`)

### Ask the user

> PR <number> targets a repo without Mergify merge-queue configuration.
> To use Mergify auto-merge, I'll add a minimal `.mergify.yml` with a merge-queue rule
> on a separate branch and open a setup PR.
> Proceed?

If declined, set `MERGIFY_AVAILABLE="declined"` and stop.

### Write the config

Fetch the Mergify docs before writing — never invent config from memory. See [`../mergify/config.md`](../mergify/config.md) if it exists; otherwise use the minimal config below.

Minimal config:

```yaml
# .mergify.yml — generated by pr-babysit
queue_rules:
  - name: default
    merge_method: squash
    merge_bot_account: null

pull_request_rules:
  - name: auto-merge when CI passes and approved
    conditions:
      - check-success-or-neutral=~ci
      - "#approved-reviews-by>=1"
      - -draft
      - -closed
    actions:
      queue:
        name: default
```

### Validate

```bash
mergify config validate
```

If it fails, fix and retry (max 2 attempts). If still failing, report the error and stop.

### Open a setup PR

Do NOT commit to the PR's branch. Create a separate branch:

```bash
git checkout -b chore/add-mergify-config <base_ref>
git add .mergify.yml
git commit -m "ci: add Mergify merge-queue configuration"
git push origin chore/add-mergify-config
gh pr create \
  --title "ci: add Mergify merge-queue configuration" \
  --body "Adds a minimal Mergify config with merge queue. Auto-generated by pr-babysit." \
  --base <base_ref>
```

Report: "Created PR #<N> to add Mergify config. Once merged, Mergify merge queue will be available."
Set `MERGIFY_AVAILABLE="bootstrapping"` (with the setup PR number).

## Report to Hermes

Include `MERGIFY_AVAILABLE` in the final report:

> Mergify: <configured|installed|none|declined|bootstrapping>
> Config file: <path or "not found">
> Setup PR: #<N> (if bootstrapping)
