# Mergify config template — role model (lint-arwaky)

This template is the role model for `pr-babysit setup`. It is based on the
lint-arwaky repo's `.mergify.yml` and is designed to be customized per-repo.

## How to use

`pr-babysit setup` collects repo facts (base branch, CI checks, timeout, etc.)
and user customization answers, then substitutes them into this template to
produce a repo-specific `.mergify.yml`.

## Security: author gate (MANDATORY)

The template MUST include `author = rakaarwaky` in both `queue_rules.queue_conditions`
and `merge_protections_settings.auto_merge_conditions`. This ensures only PRs from
the repository owner (`rakaarwaky`) are processed by Mergify. PRs from any other
author are automatically rejected at the queue level.

## Template (all `<...>` are placeholders)

```yaml
# .mergify.yml — generated by pr-babysit setup
# Role model: lint-arwaky/.mergify.yml
# Security: only PRs authored by `rakaarwaky` are allowed in the queue
# Customize: base branch, CI checks, timeout, parallelism, methods, approvals,
#            priority rules, stale cleanup, welcome comment, keep-up-to-date

defaults:
  queue_rule:
    # Update the PR with latest main before running CI on the integration
    # commit. `merge` rather than `rebase` when GitHub Rulesets enforce
    # strict_required_status_checks_policy (rejects force-pushes).
    update_method: <merge|rebase>
    merge_method: <squash|merge|rebase>
    # Size this against cold-cache CI duration per check, not warm local runs.
    # Evidence from lint-arwaky: a 5min timeout dequeued PR #683 with all
    # checks green; 15min clears cold runs with room for slower runners.
    checks_timeout: <duration>
    merge_conditions:
      # One `check-success = <name>` per CI check that must pass before merge.
      # Detect names from the PR's latest commit check-runs.
      - check-success = <check-1>
      - check-success = <check-2>
      # ... add one per detected CI check ...

merge_queue:
  # Serial mode (1): PRs tested one at a time against the latest base branch
  # tip. Guarantees no PR breaks main by itself but fails in combination.
  max_parallel_checks: <N>
  status_comments: outcomes
  queue_controls_comment: true

merge_protections_settings:
  # Auto-queue every non-draft, conflict-free PR targeting the base branch.
  # Security: only PRs authored by rakaarwaky are allowed.
  auto_merge_conditions:
    - base = <BASE_BRANCH>
    - -draft
    - -conflict
    - author = rakaarwaky
  post_comment: true
  reporting_method: check-runs

queue_rules:
  - name: default
    # Security: only PRs authored by rakaarwaky are allowed in the queue.
    queue_conditions:
      - base = <BASE_BRANCH>
      - author = rakaarwaky

# ── Priority rules (optional) ─────────────────────────────────────────────
{% if include_priority_rules %}
priority_rules:
  - name: hotfixes-first
    conditions:
      - label = hotfix
    priority: high
    allow_checks_interruption: true
  - name: refactors-last
    conditions:
      - label = refactor
    priority: low
{% endif %}

pull_request_rules:
  # ── Keep PRs up to date with base branch (optional, recommended) ────────
  {% if include_keep_up_to_date %}
  - name: keep-prs-up-to-date
    conditions:
      - base = <BASE_BRANCH>
      - -draft
      - -merged
      - -closed
      - -conflict
    actions:
      update: {}
  {% endif %}

  # ── Warn on conflicts ───────────────────────────────────────────────────
  - name: warn-on-conflicts
    conditions:
      - conflict
      - -merged
      - -closed
    actions:
      label:
        add:
          - conflict

  # ── Stale cleanup (optional) ────────────────────────────────────────────
  {% if include_stale_cleanup %}
  - name: stale-cleanup
    conditions:
      - base = <BASE_BRANCH>
      - -merged
      - -closed
      - -label = stale
      - updated-at < 14 days ago
      - created-at < 30 days ago
    actions:
      comment:
        message: >
          This PR has been open for 30 days with no commits for 14. If you're still working on it, push a commit or leave a comment. Otherwise, this PR will auto-close in 7 days.
      label:
        add:
          - stale

  - name: close-abandoned-stale
    conditions:
      - base = <BASE_BRANCH>
      - -merged
      - -closed
      - label = stale
      - updated-at < 7 days ago
    actions:
      close:
        message: 'Closed automatically — no activity for 7+ days after a stale warning.'
      label:
        remove:
          - stale
  {% endif %}

  # ── Welcome comment on new PRs (optional) ───────────────────────────────
  {% if include_welcome_comment %}
  - name: welcome-new-pr
    conditions:
      - base = <BASE_BRANCH>
      - -merged
      - -closed
      - -label = stale
      - created-at < 5 minutes ago
    actions:
      comment:
        message: >
          Thanks for the PR! CI is running — the merge queue will pick it up automatically once all checks pass.
  {% endif %}

  # ── Auto-merge when CI passes [and approved] ────────────────────────────
  - name: auto-merge-queue
    conditions:
{% if required_approvals >= 1 %}
      - "#approved-reviews-by>=<required_approvals>"
{% endif %}
      - check-success-or-neutral=~ci
      - -draft
      - -closed
      - author = rakaarwaky
    actions:
      queue:
        name: default

  # ── Notify when a PR merges ─────────────────────────────────────────────
  - name: merged-notification
    conditions:
      - merged
      - base = <BASE_BRANCH>
    actions:
      comment:
        message: Merged via the merge queue. Thanks for the contribution!

scopes:
  source:
    files: {}
```

## Customization placeholders

| Placeholder | Source | Example |
|-------------|--------|---------|
| `<BASE_BRANCH>` | detected default branch | `main`, `master`, `develop` |
| `<check-N>` | detected CI check names | `Clippy`, `Build`, `Tests` |
| `<duration>` | user answer / `15min` default | `15min`, `20min`, `10min` |
| `<N>` (max_parallel_checks) | user answer / `1` default | `1`, `2`, `3` |
| `<merge|rebase>` (update_method) | user answer / `merge` default | `merge`, `rebase` |
| `<squash|merge|rebase>` (merge_method) | user answer / `squash` default | `squash`, `merge`, `rebase` |
| `<required_approvals>` | user answer / `0` default | `0`, `1`, `2` |
| `{% if ... %}` blocks | user yes/no answers | `yes` → include, `no` → omit |

## Validation

```bash
mergify config validate
```

If the `mergify` CLI is not installed, validate YAML syntax locally; live
validation happens on GitHub after the config PR merges.
