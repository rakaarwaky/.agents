# Step 4 — Detect & Bootstrap Mergify

Run when `ship` argument is true and the repo's Mergify status is unknown. Determines whether Mergify merge-queue is available and bootstraps it if missing.

## Detect Mergify

Check in this order (stop at first positive):

### 1. Config file in the worktree

```bash
for f in .mergify.yml .mergify.yaml .mergify/config.yml .mergify/config.yaml .github/mergify.yml .github/mergify.yaml; do
  if [ -f "$f" ]; then
    MERGIFY_CONFIG="$f"
    MERGIFY_AVAILABLE="configured"
    break
  fi
done
```

### 2. Mergify check-runs on the PR

```bash
gh api "repos/$OWNER_REPO/commits/$(gh pr view <number> --json headRefOid -q .headRefOid)/check-runs" \
  -q '.check_runs[] | select(.app.slug == "mergify") | .name' 2>/dev/null | head -1
```

Non-empty result → `MERGIFY_AVAILABLE="installed"` (app installed, no local config).

### 3. Default

No config, no check-runs → `MERGIFY_AVAILABLE="none"`.

## Bootstrap `.github/workflows/mergify.yml` (when `MERGIFY_AVAILABLE` is `"none"` or `"installed"`)

Only when `ship` is `true`. If `ship` is `false`, record the detection and move on.

### Ask the user

> PR <number> targets a repo without Mergify merge-queue configuration.
> To use Mergify auto-merge, I'll add a minimal `.github/workflows/mergify.yml` with a merge-queue rule
> on a separate branch and open a setup PR.
> Proceed?

If declined, set `MERGIFY_AVAILABLE="declined"` and skip to the direct-merge path in Step 7.

### Write the config

Fetch the Mergify docs before writing — never invent config from memory. The authoritative template is [`templates/mergify.yml`](../../../templates/mergify.yml).

**Security gate is mandatory.** Every config this lane writes MUST include `author = rakaarwaky` in `queue_rules.queue_conditions` and in `merge_protections_settings.auto_merge_conditions`. A config without that condition lets non-owner PRs into the merge queue and violates SOUL.md.

Minimal config:

```yaml
# .github/workflows/mergify.yml — generated by pr-babysit
queue_rules:
  - name: default
    merge_method: squash
    merge_bot_account: null
    # Security: only PRs authored by rakaarwaky are allowed in the queue.
    queue_conditions:
      - author = rakaarwaky

merge_protections_settings:
  # Security: only PRs authored by rakaarwaky are auto-queued.
  auto_merge_conditions:
    - author = rakaarwaky
  post_comment: true
  reporting_method: check-runs

pull_request_rules:
  - name: auto-merge when CI passes and approved
    conditions:
      - check-success-or-neutral=~ci
      - "#approved-reviews-by>=1"
      - -draft
      - -closed
      - author = rakaarwaky
    actions:
      queue:
        name: default
```

### Validate

```bash
mergify config validate
```

If it fails, fix and retry (max 2 attempts). If still failing, report the error and fall back to direct merge.

Also verify the author gate is present before opening the PR:

```bash
grep -c "author = rakaarwaky" .github/workflows/mergify.yml   # must be >= 2
```

If that prints `0`, stop — do not open a setup PR with an unprotected queue.

### Open a setup PR

Do NOT commit to the PR's branch. Create a separate branch:

```bash
git checkout -b chore/add-mergify-config <base_ref>
git add .github/workflows/mergify.yml
git commit -m "ci: add Mergify merge-queue configuration"
git push origin chore/add-mergify-config
gh pr create \
  --title "ci: add Mergify merge-queue configuration" \
  --body "Adds a minimal Mergify config with merge queue. Auto-generated by pr-babysit." \
  --base <base_ref>
```

Report: "Created PR #<N> to add Mergify config. Once merged, Mergify merge queue will be available."
Set `MERGIFY_AVAILABLE="bootstrapping"` (with the setup PR number).

## Security gate on existing configs

Before leaving this step, verify a config that is already present carries the author gate:

```bash
grep -c "author = rakaarwaky" "$MERGIFY_CONFIG"
```

If the count is `0`, the queue is unprotected. Report to the owner and open a separate PR adding the gate via `/pr-babysit setup`; do not queue any PR in this repo until the gate lands.

## Report to Hermes

Include `MERGIFY_AVAILABLE` in the final report:

> Mergify: <configured|installed|none|declined|bootstrapping>
> Config file: <path or "not found">
> Setup PR: #<N> (if bootstrapping)
