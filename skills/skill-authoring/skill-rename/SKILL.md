# Rename a Hermes skill

A skill's frontmatter `name` is its slash command. Renaming = change the folder, the `name` field, and every place that names the skill (slash refs, sibling cross-refs, registry, tool alias maps), then verify nothing still points at the old name.

## Rules

| ID | Rule | Check |
|----|------|-------|
| R1 | **Gate 0 before slug commit.** Check the new slug against `hermes_cli/commands.py` `COMMAND_REGISTRY` before renaming; a built-in collision silently strips the slash command — the built-in wins and the skill becomes reachable only via `/skill <slug>`. If it collides, pick a different slug (e.g. `plan` collides with built-in `/plan`; `planner` does not). | `resolve_command('<new-slug>')` returns `None`; or grep the registry returns zero hits. |
| R2 | **Rename the directory first.** `git mv` the skill folder to the new slug; the frontmatter `name` and heading are updated in `SKILL.md` after the move. | `ls skills/<category>/<new-slug>/SKILL.md` exists; old directory gone. |
| R3 | **Frontmatter `name` matches directory.** After the move, `SKILL.md` `name:` equals the new directory name and the `#` heading reflects the new name. | `sac lint` reports no `name-mismatch`. |
| R4 | **Change skill-NAME references; rename domain-CONCEPT words only when explicitly requested.** By default keep the skill's own output terminology (documents, IDs, personas such as `design-document` / `design-doc-*` / `DESIGN_ID`) — only the skill identity and slash command change. If the user explicitly asks to rename domain terms, rename the persona files (`<skill>-writer.toml`, `<skill>-reviewer.toml`) and artifact name tokens alongside the slug. | `grep -r` old slug hits only identity references unless domain rename was requested; persona files follow the slug when renamed. |
| R5 | **Keep the legacy alias ONLY when the user has not asked for a clean break.** Default to keeping the old slug as a legacy alias so pre-existing invocations resolve. But when the user says "no legacy or alias", "remove all legacy", or similar, PURGE instead: delete the old slug from every alias map, drop it from argparse `choices=` lists, delete superseded duplicate artifacts (e.g. old `design-doc-*.toml` personas when `plan-doc-*` replaces them), and rewrite the old command mentions in trigger text to the new slug. No backward-compat entry survives a purge. | Purge: sweep grep of the shipped scope for the old slug returns zero hits; alias maps contain only the new slug; `choices=` lists do not contain the old slug. |
| R6 | **Sibling cross-refs updated.** Grep the whole skills tree for the old slug and `/<old>`; update refs in OTHER skills that call this one (go-back pointers, sibling-skill lists, trigger text). Distinguish skill-identity refs from domain strings that merely contain the old slug as a substring — a package id like `google-workspace-mcp`, a binary path `vendor/<old>-mcp/`, an XDG dir `~/.config/<old>-mcp/`, or a server prefix `mcp__<server>__` is domain terminology, not a skill pointer, and must NOT be rewritten. | `grep -r '<old-slug>'` of the skills tree returns zero stale hits except domain substrings (`<old>-mcp`, `vendor/<old>`, `mcp__…`) that are correct as-is. |
| R7 | **Registry rebuilt.** Update the `skills/catalog.json` entry name plus any description or when-to-use that names the skill or `/<old>`; run `sac catalog --build`. | `sac read <new-slug>` resolves; catalog reflects new frontmatter. |
| R8 | **Update only the alias maps that key on SKILL names — never touch tool/manifest-ID tables.** Skill-name alias maps, subdir aliases, doc lists of which skills use the tool, run-summary docstrings, and argparse `choices=` lists that enumerate accepted skill-name subdirs: add the new slug and keep the legacy alias (do not replace in place, which drops the old choice). But a table whose keys are tool/manifest IDs (e.g. `ALIAS_TABLE` mapping a tool id to a manifest package id, `INSTALL_OVERRIDES`, `LAUNCHER_NAMES`, `*_DATA_DIR`) is NOT a skill registry — adding a skill slug there misregisters an installer alias and points the resolver at a tool that was never installed. Leave tool-ID tables untouched. | The only maps that changed are keyed on skill slugs; a table keyed on tool/manifest IDs is unchanged; `choices=` lists contain both slugs. |
| R9 | **Scope and iteration ceilings.** Touch only: the skill directory, sibling skills with cross-refs, `skills/catalog.json`, and tool alias-map files. Max 2 sweep-repair iterations if stale hits remain. Forbidden: editing files outside the rename scope; deleting content without archiving it first. | `git diff --cached --name-only` is a subset of rename-scope files. |
| R10 | **Branching.** IF the new slug collides with a built-in command (Gate 0) -> pick a different slug. IF `sac lint` reports `name-mismatch` -> fix the frontmatter `name:`, not the directory. IF a sweep grep returns stale hits -> re-grep and fix only the named owner (R6 sibling, R7 registry, or R8 alias). IF `catalog.json` fails to parse -> restore from the pre-edit SHA and retry the registry edit. | Each branch has a named action and recovery path. |
| R11 | **Failure fallback.** If `git mv` fails (path exists) -> verify the destination is empty and retry. If `sac catalog --build` fails -> `git add skills/catalog.json && git commit` as a fallback rebuild. If a dependent tool test fails -> read the failure, locate the old-slug reference the test exercises, fix it, and re-run. | Each failure has symptom, cause, and recovery command. |
| R12 | **Completion.** Case-insensitive sweep grep of the affected tree for the old slug and `/<old>` returns zero stale hits except intentional legacy-alias mentions; `catalog.json` parses as JSON; dependent tool test suites pass. | Sweep grep clean; `python -c 'import json; json.load(open("skills/catalog.json"))'` exits 0. |
| R13 | **Scope the sweep to the shipped surface, never the whole repo.** A case-insensitive search for the old slug across the skills tree drags in `.venv/`, `.export/`, Rust `target/`, and embedded third-party schema — hundreds of noise hits that bury the real stale refs. Restrict the verification sweep to shipped files: the renamed skill's `.md`/`.py`/`.toml` under its category dir, the `personas/*.toml`, the tool's `src/` + `tests/` + doc files, and `skills/catalog.json`. Exclude `.venv`, `__pycache__`, `.git`, `.archive`, `.export`, and `target/`. | The verification search returns only in-scope files; no venv/target/export paths appear in its output. |
| R14 | **After a bulk word replace, fix casing and collision artifacts.** A mechanical `\b<old>\b`→`<new>` replace mangles two things: (a) capitalized domain words become wrong case (`"# Design Doc"`→`"# plan Doc"`, `"## Design Document"`→`"## plan Document"`) — fix every header/heading, label, and sample title that gained a lowercase word; (b) a quoted token replaced in place can create a duplicate entry in an enum/list (`choices=[..., "plan", "plan", ...]`) or delete a needed key. Search the touched files for the new token doubled, and for any list literal that now has duplicate values, before declaring done. | `search_files` for the new token doubled; no duplicate list literals; no lowercase mid-word in headings. |
| R15 | **Duplicate artifacts left behind by a partial rename must be deleted, not merged.** When a rename creates `plan-doc-*.toml` alongside the still-present `design-doc-*.toml`, the old files are stale copies. Diff them to confirm the new ones are complete (old name fields gone, new terms present), then remove the legacy files — never leave both on disk. | Only the new-slug persona files exist under `personas/`; a file listing shows no old-slug `*doc-*` files. |
